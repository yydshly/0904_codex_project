# TopHub 能力图谱

> 将“今日热榜”拆解为来源、采集、标准化、历史沉淀、分析视图与自动化输出六层能力，明确它作为互联网注意力雷达的价值和边界。

![TopHub 热点数据采集与处理概览，展示来源、节点规则、处理流水线与输出方式](images/architecture.svg)

## 提交摘要

TopHub 本质上是一个**以中文互联网平台为主、同时覆盖部分海外技术社区的公开热榜聚合与信号服务**。它不生产新闻，也不等于全网舆情系统；它把各平台已经形成的榜单，通过节点规则采集并整理成统一数据，再提供浏览、订阅、历史回溯、通知和 API 等输出。

- 能力：多源热榜聚合、订阅分组、搜索回溯、热点再组织、追踪提醒和结构化数据服务。
- 来源：微博、百度、知乎、微信、今日头条、V2EX、豆瓣、虎扑、GitHub、抖音等公开榜单，以及用户定制节点。
- 获取：官方文档明确支持公开 HTML 页面和 JSON 接口；RSS、页面内部请求及浏览器渲染属于可扩展采集手段，不能据此断言当前生产后端已经采用。
- 处理：节点规则配置 → 周期拉取 → 字段提取 → 标准化与校验 → 榜单快照和历史沉淀 → 多渠道输出。
- 输出：Web 与移动端阅读、订阅和日报、历史与榜中榜、关键词机器人、CSV、REST API 和 Webhook。
- 意义：把需要人工逐站查看的即时榜单，转成低成本、可回溯、可接入业务流程的外部注意力信号。

## 为什么关注

TopHub 表面上是一个热榜导航站，实际已经形成“榜单采集—统一数据—历史快照—搜索追踪—API 与通知”的信号服务链路。本项目不重复展示具体热搜，而是回答七个更适合产品与技术决策的问题：它有什么能力、数据来自哪里、如何处理、输出什么、为什么有价值、可以怎样扩展、适合哪些场景。

## 核心能力

- 多源聚合：集中展示搜索、社交、新闻、内容、社区、开发、商业等领域的公开榜单。
- 主动订阅：用户按节点和分组组织信息，形成可控的信息入口。
- 历史回溯：保存上榜记录与榜单快照，使即时排行成为时间序列资产。
- 热点再组织：以日报、榜中榜、话题聚合和热点日历提供派生视图。
- 追踪自动化：通过关键词、来源、排名和热度规则进行过滤、提醒与机器人推送。
- 结构化交付：通过 CSV、Excel、REST API 和 Webhook 服务下游系统。

## 来源与处理

### 已由官方资料确认的入口

- `match`：针对公开 HTML 榜单配置采集区域、单条记录区域和正则提取规则。
- `json`：针对 JSON 数据配置字段路径，提取标题、简介、缩略图、链接和附加信息。
- 官方数据服务：提供最新榜单、历史数据集、快照、全网搜索、榜中榜、热点日历和 Webhook 等接口。

官方使用指南列出的典型平台包括微信公众号、今日头条、百度、知乎、V2EX、微博、贴吧、豆瓣、天涯、虎扑、GitHub 和抖音，并说明这些主要榜单约每 5 分钟更新一次。

### 可扩展但不能视为已公开实现的入口

- RSS / Atom：适合站点主动提供订阅源的情况。
- XHR / Ajax 或页面内嵌 JSON：适合榜单页面实际由内部数据请求驱动的情况。
- 浏览器渲染：只应作为 JavaScript 动态页面的高成本兜底方案。
- 合作方推送、授权数据集和人工导入：适合无法稳定公开拉取或有许可要求的数据。

### 必要处理链

1. **配置节点规则**：记录来源地址、提取类型、内容区域和输出字段。
2. **周期触发与请求**：按更新频率执行，控制并发、超时、限速和重试。
3. **解析提取**：从 HTML 或 JSON 中提取标题、链接、图片和附加热度。
4. **统一整理**：映射成标题、链接、来源、排名、热度、时间等标准字段，并进行基础校验与去重。
5. **快照沉淀**：保存当前榜单状态和历史上榜数据，为检索、追踪和趋势分析提供时间维度。
6. **输出交付**：面向用户展示，或通过 CSV、API、Webhook 和通知机器人供其他流程消费。

具体后端框架、数据库、反爬策略、跨平台去重、话题相似度与榜中榜排序算法没有公开。网页和架构图对这部分只做必要能力推断，不把它们描述成已确认事实。

## GitHub 与源码判断

截至本次调研，没有找到能够确认是 `tophub.today` 当前生产系统完整源码的官方 GitHub 仓库。GitHub 上的 [`tophubs/TopList`](https://github.com/tophubs/TopList) 是 Go 编写的同类热榜聚合项目，包含定时爬虫、MySQL 和 HTTP 服务，但其 README 指向 `mo.fish` / `tophub.fun`，因此只能作为相关实现参考，不能直接视为 TopHub 当前后端源码。

## 使用场景

- 内容运营：发现选题、生成早晚报、观察热点生命周期。
- 品牌与公关：追踪品牌词、竞品词和潜在风险，触发人工研判。
- 产品与战略：观察行业、公司和政策信号，辅助外部环境扫描。
- 研究分析：利用历史快照比较事件传播速度、持续时间和覆盖平台。
- 数据与 AI：把热点数据接入知识库、Agent、工作流或内部看板。

## 可扩展方向

1. 数据底座：采集健康度、来源版本、延迟、字段质量和数据血缘。
2. 语义层：事件聚类、实体识别、相似标题归并和主题演化。
3. 指标层：跨平台热度归一化、增速、持续时间和传播范围。
4. 可信层：来源等级、交叉验证、争议标记和事实核查入口。
5. 业务层：与客户反馈、销售、搜索、工单和竞品数据库结合。
6. 行动层：自动简报、任务创建、通知升级和反馈闭环。

## 网页设计

网页采用“信号情报工作台”而不是传统报告排版：

- 首屏提供可交互的五段数据链路，点击阶段即可查看该层输入和职责。
- 能力地图区分基础聚合、信息组织、热点再组织、自动化与数据服务。
- 使用场景支持按战略、内容、品牌、产品、研究和开发角色切换。
- 扩展雷达按数据底座、语义层、指标层、可信层、业务层和行动层排序。
- 证据标记区分“官方文档可确认”和“依据产品形态推断”。

## 本地运行与验证

在仓库根目录执行：

```powershell
python -m http.server 4177 --bind 127.0.0.1 --directory projects/040-tophub-capability-atlas/demo
```

然后访问 <http://127.0.0.1:4177/>。

已验证：页面可从本地静态服务器正常加载；处理链路和角色场景支持鼠标及键盘切换；布局包含桌面与移动端响应式规则。

## 可复用的启发

- 通用采集层可以购买或复用，真正形成差异化的是行业词表、事件归并、重要度评分与业务反馈。
- 即时榜单只有浏览价值；保存时间、排名和快照后，才具备研究与预警价值。
- 公共热点应作为上游线索，而不是最终结论；高价值产品需要与组织私有数据结合。
- 输出应覆盖“人读、辅助判断、触发流程、机器调用”四种消费方式。

## 局限与边界

- 上榜内容并不代表全网讨论，长尾内容可能被遗漏。
- 热度不等于真实性，也不能替代事实核查。
- 不同平台热度口径不同，原始数值不能直接横向比较。
- 官方说明主要获取榜单标题和链接，并不等于拥有或完整存储原文。
- 生产集成应优先使用官方 API，不应大量自动化抓取 TopHub 网页。

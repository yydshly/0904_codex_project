02 / PRINCIPLE & USE CASES

一张图看懂，
Arnis 到底做什么。

它不是地图查看器，也不是游戏编辑器。它把分散的开放地理数据，按可解释的规则编译成可以继续进入、修改和复用的方块世界。

01INPUT / 真实地点

收集开放地理数据

输入经纬度范围；读取 OSM 建筑、道路、水系，叠加 DEM 高程、土地覆盖、树冠和可选地标模型。

得到：不同来源、不同尺度的空间要素
02ENGINE / 语义编译

理解对象并解决冲突

把标签解释成道路、建筑、桥梁和植被规则；补全缺失高度与材质，并处理道路贴地、水体雕刻和对象避让。

核心：地理语义 → 方块放置规则
03OUTPUT / 世界资产

写出可操作的世界

按 Chunk 写入 Minecraft Java、Bedrock 或 Luanti 世界；结果可以进入游戏、人工精修、添加玩法或交给其他转换器。

得到：世界存档，而不是一张图片
本网页额外做了什么

Java .mca 世界→解析 Block State→合并可见网格→Three.js 3D

这是本研究项目增加的 Web 适配层，不是 Arnis 当前原生输出；上面的 Minecraft 世界才是原库直接交付。

03 / BUILD IT FROM ZERO

从经纬度开始，
到浏览器里漫游。

这里有两条相接但不混淆的流水线：Arnis 负责把地理数据编译成游戏世界；本项目增加一个只读适配器，把世界存档转换成浏览器可高效绘制的网格。

  1. 01SELECT

    确定区域与模式

    给出经纬度 bbox、比例和 geo-terrain / geo-only / terrain-only。

    INPUT · 经纬度↓
  2. 02GENERATE

    Arnis 编译世界

    获取 OSM、Overture、高程与地表数据，生成 level.dat、Region 和 Chunk。

    OUTPUT · .mca↓
  3. 03DECODE

    读取 Anvil / NBT

    构建脚本解压 Region Chunk，读取 Section 调色板和压缩后的 Block State。

    OUTPUT · 方块坐标↓
  4. 04MESH

    只保留可见表面

    剔除被遮挡的内部面，再用贪心合并相邻同材质矩形，降低浏览器负担。

    OUTPUT · QUAD BIN↓
  5. 05RENDER

    Three.js 实时绘制

    按材质建立 BufferGeometry，加入相机、光照、缩放、旋转和能力回退。

    OUTPUT · 可交互 3D

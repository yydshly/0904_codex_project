# Open2Hub 热榜聚合架构

> 以 Open2Hub 的 REBANG 热榜为研究对象，将其拆解为“信息来源—采集接入—数据处理—数据存储—聚合服务—产品展示”六个模块，作为建设同类热点聚合能力的外部参考。

![Open2Hub 模块化架构图，展示公开信息从来源采集到产品展示的六段处理链路，以及来源管理、异常监控、失败重试和合规治理组成的横向保障层](images/architecture.svg)

## 项目摘要

Open2Hub 旗下的 REBANG 是一个以中文互联网平台为主的公开热榜索引。它不生产新闻正文，而是定时获取各平台公开榜单中的标题、排名和原文链接，完成基础整理后按综合、新闻、财经、科技、娱乐、体育、视频和其他频道展示。

- **信息来源**：覆盖社交、新闻、财经、科技、文娱、体育等公开热榜；2026-09-05 快照包含 131 个榜单卡片和 72 个不同来源名称。
- **采集接入**：从公开榜单页面或公开接口获取数据；不同平台需要独立适配获取和解析方式。
- **数据处理**：将不同来源整理为平台、子榜、排名、标题、链接和采集时间等统一字段。
- **数据存储**：现网可确认会缓存标题和链接；是否保存完整历史快照以及采用何种数据库尚未公开。
- **聚合服务**：按频道组织榜单，并生成面向页面的可读取结果。
- **产品展示**：提供极简热榜、来源跳转和每日摘要，降低逐站浏览的成本。

## 值得复用的能力

1. 把平台及其子榜单整理为可维护的来源目录。
2. 用独立适配器隔离不同平台的接口和页面差异。
3. 通过统一数据模型降低展示层和下游系统的接入成本。
4. 使用定时采集与缓存，避免用户访问时同时请求大量外部平台。
5. 将异常监控、失败重试、来源标注和合规控制作为横向能力。
6. 在基础聚合之上继续建设历史趋势、跨平台事件聚类、订阅告警和行业情报。

## 证据边界

- [官方说明](https://top.open2hub.com/rebang-about.html)确认：数据来自公开可见的热榜页面，只缓存标题、链接等索引信息，点击后回到原平台。
- [关联 Gitee 仓库](https://gitee.com/zhaochenchen/REBANG)目前只有 README，没有采集器、来源配置或部署代码。
- [open2hub GitHub 仓库](https://github.com/open2hub/open2hub.github.io)对应 `blog.open2hub.com` 静态博客，不是 REBANG 采集后端源码。
- 因此，本项目区分“网页和官方说明可以确认的事实”与“为解释产品形态所作的必要工程推断”，不把推断描述为已公开实现。
